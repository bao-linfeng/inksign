## 1. 产品概述

### 1.1 产品定位

InkSign（墨签）是一款**免费优先、轻量、隐私优先的浏览器端 PDF 可视化签名工具**。用户无需注册或安装客户端，即可在本地浏览器中打开 PDF，手写或上传签名、放置到指定页面、调整位置和尺寸，并导出带有签名外观的 PDF。用户可选择将签名保存在本设备，日后签署合同等文件时直接复用。

**核心路径：** 选择 PDF → 创建或从签名库选择签名 → 放置并调整（可批量放置、添加日期） → 预览检查 → 下载签名后 PDF。

**边界说明：** MVP 实现的是将手写或图片签名作为**可视化签名外观**写入 PDF，不提供基于数字证书的密码学数字签名、身份核验、时间戳或法律效力保证。产品文案不得将两者混同。

### 1.2 目标用户

- 个人用户：在报名表、确认单、申请书等 PDF 文件上签字。
- 轻办公用户：需要快速完成少量 PDF 手写签署。
- 反复签署用户：经常签合同、协议，希望写一次签名、之后直接复用。
- 隐私敏感用户：希望 PDF 不上传服务器。

### 1.3 目标与成功指标

1. 新用户不阅读教程即可完成首次签名。
2. 常规桌面流程目标 3 分钟内完成（体验目标，需通过测试验证）；使用已保存签名的回访用户目标 1 分钟内完成。
3. 默认无登录、无服务器存储、无上传文件请求。
4. 签名位置准确，导出后跨常见阅读器正常显示。
5. 埋点如需引入，必须为隐私友好且经用户同意，MVP 默认无第三方分析 SDK。

- 纸质签名图片自动去背景（可以后续增强）。

## 3. 核心用户流程

1. 用户进入首页，看到明确的“选择 PDF 文件”入口及“文件仅在本地处理”提示。
2. 用户选择或拖入 PDF；系统校验并显示加载状态。
3. PDF 载入后进入编辑工作区；显示页码、页面缩略/导航入口、缩放和工具栏。若文档已含数字签名，此时即给出警告（见 FR-01）。
4. 点击“添加签名”：签名库非空时默认显示“我的签名”，点选即可使用（设有 PIN 的需先解锁）；也可“手写”或“上传图片”新建，新建时可勾选“保存到本设备”。
5. 点击目标页面放置签名；可拖动、缩放、删除；可将选中签名“应用到多页”；可添加签署日期。
6. 点击“导出 PDF”，系统将签名与日期图像写入对应 PDF 页面的指定坐标；完成后下载。
7. 用户可继续调整并再次导出；关闭/刷新后 PDF 与未保存的签名消失，签名库中已保存的签名保留（刷新前有未保存操作时提示取决于浏览器支持）。

## 4. 信息架构与页面

### 4.1 首页（未导入状态）

- Logo：InkSign / 墨签。
- 主标题：为 PDF 轻松添加手写签名。
- 副标题：无需注册 · 文件在本地处理 · 一键导出。
- 主按钮：选择 PDF 文件。
- 拖拽热区：将 PDF 拖到此处。
- 简短说明：本工具提供可视化签名，不等同于证书数字签名。
- 签名库入口：“我的签名（N）”，可在不打开 PDF 的情况下查看、新建、删除、导出签名。

### 4.2 PDF 编辑工作区

- **顶部栏：** Logo、当前文件名、重新打开、导出 PDF。
- **左侧栏（桌面）：** 页面导航（可用缩略图，性能不足时先使用页码列表）。
- **中央画布：** 连续滚动页面，带签名叠加编辑层。
- **右侧/浮动工具：** 新建签名、我的签名、添加日期；选中实例时显示删除、尺寸调整、“应用到多页”。
- **底部/顶部辅助：** 当前页码、放大缩小、适合宽度。
- **移动端：** 收起侧栏；通过底部工具条完成添加、删除、导出等操作。

### 4.3 创建签名弹窗

- Tab A：我的签名（签名库非空时为默认 Tab）。显示已保存签名的缩略图；加密签名显示锁图标，点击后输入 PIN 解锁。
- Tab B：手写。画布支持 pointer events、清空、预览、确认。
- Tab C：上传。支持 PNG/JPG/WebP，显示裁切后的内容边界预览（裁去透明外围空白，不裁去笔迹）。
- 手写与上传确认前提供“保存到本设备”复选框（默认不勾选），勾选后可选设置 PIN 并填写签名名称（如“全名”）。
- 必须有“取消”；空白手写签名无法确认。

### 4.4 签名库管理

- 列表：缩略图、名称、创建时间、是否加密。
- 操作：重命名、下载透明 PNG、删除、清空全部；设置、修改或移除 PIN。
- 常驻提示：签名保存在本浏览器，清理浏览器数据会丢失，建议下载备份；请勿在公共或共用电脑上保存。
- 显示存储状态：浏览器是否已授予持久化存储。

## 5. 详细功能与验收标准

### FR-01 文件导入（P0）

**要求：** 点击选择或拖放单个 PDF；读取为浏览器内存中的 ArrayBuffer；文件名显示在顶部。

- 格式校验：读取文件头，前 1024 字节内须出现 `%PDF-`；不依赖扩展名或 MIME。
- 加密检测需区分两种情况：
  - **需要打开密码**：PDF.js 抛出 `PasswordException`，提示“暂不支持受密码保护的 PDF”。
  - **仅有权限限制（owner password）**：PDF.js 可以正常显示，但导出库加载时会拒绝或产生异常输出。须在导入阶段用导出库试加载一次（或检查 trailer 的 `/Encrypt`），提前提示，不得等到导出时才失败。
- 已有数字签名检测：导入时检查 AcroForm 中是否存在 `/FT /Sig` 字段或 `SigFlags`。若存在，在工作区显示醒目警告：“此文件已包含数字签名，导出后原有签名将失效。”导出库为整文件重写而非增量保存，无法保留原签名有效性。

**验收：**

- 有效 PDF 可以打开，且没有文件上传网络请求。
- 错误格式、空文件、损坏 PDF 提示可理解的错误，并允许重试。
- 建议默认上限 50 MB / 200 页（产品可配置）；超出时提示而非崩溃。
- 加密/需要密码的 PDF：MVP 先给出“不支持加密 PDF”的提示；不尝试绕过保护。仅有权限限制的 PDF 同样在导入阶段提示。
- 含已有数字签名的 PDF 在进入工作区时即显示警告。

### FR-02 PDF 预览与导航（P0）

**要求：** 按原 PDF 页面顺序显示，支持滚动、缩放（例如 50%～200%）和页码跳转；页面宽高比与旋转保持正确。

- PDF.js 资源全部自托管，构建时从 `pdfjs-dist` 复制到静态目录：
  - `cMapUrl`（`cmaps/`）与 `standardFontDataUrl`（`standard_fonts/`）：缺失时中文/日文等 CJK 字体 PDF 可能乱码或空白。
  - `wasmUrl`（`wasm/`）：pdfjs-dist 6.x 使用 WebAssembly 解码 JPEG2000、JBIG2 图像及色彩管理，同时自带无 wasm 回退。
  - `iccUrl`（`iccs/`）：色彩管理使用的 ICC 配置文件。
  - Worker 文件同源加载。
- 安全配置：pdfjs-dist 6.x 已不再使用 `eval`（v1.2 草稿中的 `isEvalSupported` 选项已被移除）；不接入 PDF.js 的脚本沙箱（不执行 PDF 内嵌 JavaScript），`enableXfa: false`，不渲染 PDF 中的 HTML 内容。
- 画布按 `devicePixelRatio` 渲染以保证高分屏清晰度，同时对单页像素数设置上限，防止移动端内存溢出。

**验收：**

- 不同页面大小及横竖版混排时展示正确。
- 缩放后签名与 PDF 内容保持相对位置不漂移。
- 大文件采用按需渲染/可视区域渲染，避免一次性绘制所有高分辨率页面。
- 含 CJK 字体（含未嵌入字体）的 PDF 显示正常，且渲染过程无第三方域名请求。

### FR-03 手写签名（P0）

**要求：** 使用 Pointer Events 支持鼠标/触屏/触控笔；输出透明背景 PNG 数据；可清空、重新写。

- 采用 `signature_pad`（持续维护，内置 Pointer Events 与按速度变化的笔画粗细）实现画板。
- 画布内部分辨率 = CSS 尺寸 × `devicePixelRatio`（建议至少 2 倍），保证导出到 PDF 后放大查看不发糊。
- 画布设置 `touch-action: none`，防止绘制时页面滚动或缩放。
- 确认时按笔迹包围盒裁切，四周保留内边距（建议 8～16 px）。

**验收：**

- 手写轨迹连续，触屏绘制时不触发页面滚动。
- 空笔迹不可保存。
- 有效笔迹保留透明背景，边界裁切需留合理内边距。
- 高分屏设备上导出的签名在 200% 缩放下无明显锯齿或模糊。

### FR-04 图片签名（P0）

**要求：** 在本地读取 PNG、JPG、WebP；生成可嵌入 PDF 的 PNG 表现形式；有清晰预览。

- 输入限制：文件不超过 10 MB；解码后长边超过 2000 px 时在本地等比缩小到 2000 px，避免内存占用和导出体积失控。
- 使用 `createImageBitmap(file, { imageOrientation: 'from-image' })` 解码，以尊重 JPG 的 EXIF 方向（手机照片常见）。
- 统一转为 PNG 字节（`Uint8Array`）后嵌入 PDF；WebP 无法直接嵌入 PDF，必须转换。

**验收：**

- PNG 透明通道在预览和导出中保持一致。
- JPG 白色背景保留，不误导用户已自动去底。
- 图片过大或解码失败时显示错误并允许重新上传。
- 带 EXIF 旋转信息的手机照片预览与导出方向正确。

### FR-05 放置与操作（P0）

**要求：** 用户选定签名后，在 PDF 某页点击放置；签名支持拖动、按比例缩放、删除，可在多页添加实例。

- 拖动与缩放基于 Pointer Events 自行实现（`setPointerCapture` + 约束在页面边界内），不引入已停止维护的拖拽缩放库。
- 手势分层：签名实例及其手柄设置 `touch-action: none`；页面空白区域保留浏览器原生滚动与双指缩放，避免手势冲突。
- 键盘可达：选中实例后可用方向键微调位置、`Delete` 删除。

**验收：**

- 放置后可被选中，显示清晰的边框与缩放手柄。
- 签名默认保持长宽比，并限制最小与最大可用尺寸。
- 操作范围限制在目标页面可见区域内；不能误拖到其它页。
- 各页面独立保存自己的签名实例，删除一处不影响其它页。
- 点击导出后，签名在 PDF 中的视觉位置与编辑时保持一致，允许不超过 2 个屏幕像素的等效偏差（在固定测试缩放条件下）。
  - **测量方法：** 固定 100% 缩放和 DPR=1，导出后用 PDF.js 以同一缩放重新渲染导出文件，比对签名包围盒与编辑态包围盒的四条边，偏差均 ≤ 2 px。该比对写成自动化测试。

### FR-06 导出 PDF（P0）

**要求：** 用 `@cantoo/pdf-lib`（`pdf-lib` 的持续维护分支，API 兼容；原版 `pdf-lib` 自 1.17.1 起已停止发版）从原 PDF 创建导出副本，将签名 PNG 嵌入对应页并生成下载 Blob。默认文件名为 `原文件名_signed.pdf`。

- 同一枚签名图像在一次导出中只 `embedPng` 一次，多个实例（含批量签名产生的实例）复用同一个图像对象，避免文件体积成倍增长。
- 坐标映射见第 6 节，必须同时处理 **CropBox 偏移** 与 **页面旋转（含签名图像本身的旋转）**。
- 导出确认处显示法律效力提示（见 FR-08 “合同场景提示”）。

**验收：**

- 导出结果可在 Chrome、Edge、Adobe Acrobat Reader 等常见阅读器中打开。
- 页面数量、纸张尺寸、方向和非签名区域视觉内容不应改变。
- 签名导出为 PDF 页面可视内容，不能再通过普通编辑层拖动。
- 有进度/忙碌状态，阻止重复提交；错误提示可重试。
- 明确告知：导出不等于证书数字签名，且无法保证与原 PDF 字节完全相同或保留既有数字签名的有效性。
- 在 90°/180°/270° 旋转页上，签名在阅读器中的显示方向为正（不是横躺或倒置）。

### FR-07 本地隐私（P0）

**要求：** 默认无后端。PDF 文件与文件名只在当前页面内存处理，**任何情况下都不持久化**。签名图像默认只驻留内存；**唯一例外**是用户主动“保存到本设备”的签名，按 FR-08 存于 IndexedDB。

- 会话签名以 `Uint8Array` / Blob 驻留内存，预览使用 Object URL，替换或删除时 `URL.revokeObjectURL`。
- 字体、图标、PDF.js 资源全部自托管，不使用 Google Fonts 等第三方 CDN。
- 用户偏好（如界面语言、日期格式）允许存 localStorage，但不得包含文件名、PDF 或签名内容。

**验收：**

- Network 检查无 PDF 内容和签名数据上传。
- 刷新页面后，之前的 PDF 和未保存的签名不自动恢复；只有用户主动保存的签名出现在签名库中。
- 浏览器存储（localStorage、IndexedDB、Cache Storage）中不存在任何 PDF 内容或文件名。
- 依赖资源可通过自有静态站点提供，避免使用无必要的第三方 SDK。
- 对用户说明“浏览器本地处理”，不要承诺浏览器或系统绝对无痕。
- 首次加载到完成导出的全过程中，不存在任何第三方域名请求。

### FR-08 签名库（P0）

**要求：** 用户可将手写或上传的签名保存到本设备浏览器，日后直接选用，无需重写；签名库内容不离开本设备。

- **存储：** IndexedDB（使用 `idb` 封装），只存签名 PNG 字节与元数据（名称、创建时间、尺寸、是否加密）。保存时调用 `navigator.storage.persist()` 申请持久化存储，并在签名库界面显示授予结果。
- **主动保存：** “保存到本设备”默认不勾选；首次保存时弹出说明，告知签名存储位置、丢失风险与共用设备风险，用户确认后才保存。
- **可选 PIN 加密：**
  - 用 Web Crypto 实现：PBKDF2-SHA256（迭代次数 ≥ 600,000，随机 16 字节盐）派生 AES-GCM-256 密钥，每条签名使用独立的随机 12 字节 IV。
  - PIN 至少 6 位，允许数字与字母；不存储 PIN，也不存储派生的密钥。
  - 解锁后的明文只驻留内存，当前会话内免重复输入；页面关闭或用户点击“锁定”后清除。
  - 忘记 PIN 无法找回，只能删除该签名后重新创建；界面需明确提示。
  - 如实告知保护范围：PIN 可以防止共用电脑的人随手使用签名，但无法抵御拿到设备数据后的离线暴力破解，不得宣传为“银行级加密”。
- **导出与导入：** 每个签名可下载为透明 PNG（文件名如 `签名_全名.png`）作为备份或在其它设备使用；导入时走 FR-04 上传流程。
- **管理：** 重命名、删除、清空全部；设置、修改或移除 PIN（修改或移除前须验证原 PIN）。
- **容量：** 每个签名不超过 2 MB（PNG 字节），最多保存 20 个；写入失败（如超出配额）时给出明确提示。
- **合同场景提示**（签名库首次保存与导出确认时显示）：“图片形式的签名不具备证书数字签名的防篡改与身份认证能力。用于重要合同时，请与对方确认是否接受，必要时使用具备 CA 认证的电子签约平台。”上线前提示文案需经法务确认。

**验收：**

- 保存签名后刷新或重开浏览器，签名库中仍可见并可直接放置使用。
- 未勾选“保存到本设备”时，刷新后签名消失。
- 加密签名在 IndexedDB 中仅以密文形式存在；PIN 错误时无法解锁，并有错误提示。
- 下载的 PNG 透明背景正确，再上传后效果与原签名一致。
- 清空全部后 IndexedDB 中无残留签名数据。
- 浏览器清除站点数据后，签名库为空且界面正常显示空状态，不报错。

### FR-09 签署日期（P0）

**要求：** 在 PDF 上放置签署日期文本，与签名一样可拖动、缩放、删除。

- 默认填入当天日期，用户可修改。
- 格式可选：`2026年11月12日`、`2026-11-12`、`2026/11/12`；用户上次选择的格式存入 localStorage 偏好。
- 字体颜色默认与签名相近的深色，可选黑、深蓝。
- **实现方式：** 用 Canvas 按高分辨率（至少 2 倍）将日期文本渲染为透明 PNG，与签名走同一放置与导出管线。这样不必向 PDF 嵌入中文字体（CJK 字体动辄数 MB，且有授权问题），预览与导出外观一致。代价是导出后的日期不能作为文本选中或检索，可以接受。
- 渲染字体使用应用自托管的字体（或系统字体回退），保证同一设备上预览与导出一致。
- 可在放置签名后一键“在签名下方添加日期”，自动对齐。

**验收：**

- 日期在预览与导出中位置、外观一致（同 FR-05 的偏差标准）。
- 中文日期格式在导出的 PDF 中正常显示，不出现方框或乱码。
- 修改日期内容或格式后，已放置的日期实例同步更新。

### FR-10 批量签名（P0）

**要求：** 选中一个已放置的签名（或日期）实例，可“应用到多页”，在所选页面的相同位置生成实例。

- 页码范围：全部页、除最后一页、仅最后一页、自定义（如 `1-3,5`，需校验输入）。
- **位置规则：** 以原实例距离最近的页面角（如右下角）为锚点，在其它页保持相同的边距与绝对尺寸（PDF 点为单位），使不同尺寸的页面上签名大小一致；超出页面时自动缩小并限制在页面内。旋转页按可见方向计算。
- 批量生成的实例归入同一组（`groupId`）：可“删除整组”；每个实例仍可单独移动或删除，单独修改后不影响组内其它实例。
- 原页面已有实例时不重复生成。

**验收：**

- 10 页 PDF 选择“全部页”，每页右下角均出现签名，与原实例边距一致。
- 横竖版混排、页面尺寸不同时，签名大小一致且不超出页面。
- “删除整组”只删除该组实例，不影响手动放置的其它实例。
- 导出文件中同一签名的图像只嵌入一次（同 FR-06）。

## 6. 关键数据结构与坐标映射

```ts
// 会话内使用的签名（来自手写、上传或已解锁的签名库条目）
type SignatureSource = {
  id: string;
  kind: "draw" | "image" | "date";
  pngBytes: Uint8Array; // 仅驻留内存，导出时直接嵌入
  previewUrl: string; // URL.createObjectURL 生成，删除时 revoke
  naturalWidth: number;
  naturalHeight: number;
  libraryId?: string; // 来自签名库时关联
};

// 签名库条目（IndexedDB 持久化）
type StoredSignature = {
  id: string;
  name: string; // 如“全名”
  createdAt: number;
  naturalWidth: number;
  naturalHeight: number;
  // 未加密：pngBytes 有值；加密：cipher/iv/salt 有值、pngBytes 为空
  pngBytes?: Uint8Array;
  encrypted: boolean;
  cipher?: ArrayBuffer; // AES-GCM 密文
  iv?: Uint8Array; // 12 字节
  salt?: Uint8Array; // 16 字节
  kdfIterations?: number;
};

type Placement = {
  id: string;
  sourceId: string; // SignatureSource.id
  pageIndex: number; // 从 0 开始
  xRatio: number; // 相对可见页面宽度，0..1（左上角为原点）
  yRatio: number; // 相对可见页面高度，0..1
  widthRatio: number;
  heightRatio: number;
  groupId?: string; // 批量签名生成的实例共享
};

type DateField = {
  sourceId: string; // 对应 kind 为 'date' 的 SignatureSource
  value: string; // ISO 日期，如 2026-11-12
  format: "zh" | "dash" | "slash";
  color: string;
};
```

坐标统一以 PDF.js 渲染后的**可见页面视口左上角**为原点存储相对比例；导出时根据页面原始旋转、CropBox/MediaBox、视口变换矩阵和 PDF 坐标系进行反向映射，避免对旋转页、裁剪页直接用 `pageHeight - y` 的简单公式。

**导出映射算法（`coordinate-transform.ts`）：**

1. 对目标页取 `viewport = page.getViewport({ scale: 1 })`（PDF.js 默认应用页面 `/Rotate`，视口原点为可见页面左上角，`page.view` 已考虑 CropBox）。
2. 由比例还原视口坐标：`x = xRatio·W`、`y = yRatio·H`、`w = widthRatio·W`、`h = heightRatio·H`，其中 `W/H` 为 `viewport.width/height`。
3. 签名在屏幕上是正向显示的，其**左下角**在视口中为 `(x, y + h)`。用 `viewport.convertToPdfPoint(x, y + h)` 得到 PDF 用户空间中的绘制原点 `(px, py)`；该函数已包含 CropBox 偏移与旋转逆变换。
4. 规范化旋转角 `r = ((page.rotate % 360) + 360) % 360`。
5. 调用 `pdfPage.drawImage(img, { x: px, y: py, width: w, height: h, rotate: degrees(r) })`。阅读器显示时会将页面顺时针旋转 `r`，而图像预先逆时针旋转 `r`，两者抵消后显示为正向。`width/height` 取视口方向上的尺寸，不需要对调。
6. 该算法须由第 10 节用例 4、5 的自动化测试验证后方可视为完成。

批量签名（FR-10）在视口坐标（PDF 点）中计算锚点与边距，再换算为各页的比例存入 `Placement`，导出时仍走上述算法。

## 7. 技术方案

| 层次       | 选型                                                                                                   |
| ---------- | ------------------------------------------------------------------------------------------------------ |
| 前端       | Vue 3.5 + TypeScript 6 + Vite 8                                                                        |
| UI         | Tailwind CSS 4 + shadcn-vue（复用模板 `@repo/ui`，基于 reka-ui）                                       |
| 图标       | `@lucide/vue`（打包进产物，无 CDN）                                                                    |
| PDF 预览   | `pdfjs-dist` 6.x，Worker 同源加载；cmaps / standard_fonts / wasm 自托管                                |
| PDF 导出   | `@cantoo/pdf-lib`（维护中的 pdf-lib 分支）                                                             |
| 签名画板   | `signature_pad` 5.x（Canvas 2D + Pointer Events）                                                      |
| 拖动/缩放  | 自行实现（Pointer Events），可借助 `@vueuse/core` 的事件工具                                           |
| 签名库存储 | IndexedDB + `idb` 8.x（轻量 Promise 封装，持续维护）                                                   |
| 签名加密   | Web Crypto API（PBKDF2 + AES-GCM），浏览器原生，无额外依赖                                             |
| 日期渲染   | Canvas 2D 渲染为 PNG，复用签名导出管线                                                                 |
| 状态       | Pinia 4 或精简 composables（不引入不必要的全局状态；store 不做持久化，签名库由专门服务读写 IndexedDB） |
| 测试       | Vitest 4（单元，含坐标映射、加密往返）+ Playwright（端到端与视觉比对）                                 |
| 部署       | 静态网站（Nginx / Caddy / Cloudflare Pages 等），按第 8 节配置 CSP                                     |
| 运行环境   | Node.js ≥ 24.22，pnpm 11.25（与模板一致）                                                              |

**选型原则：** 只选用仍在持续发版、有明确维护者的库；新增依赖前需评审其维护状态与体积。已排除：原版 `pdf-lib`（2021 年后无新版本）、`vue3-moveable`（2023 年后无更新）。

**技术原则：** 预览用 PDF.js，导出用 `@cantoo/pdf-lib`；预览层与签名交互层分离。原始 PDF 字节保留在当前会话内存，重复导出基于原文件重新合成，避免叠加重复签名。注意 PDF.js 加载时可能转移（detach）传入的 ArrayBuffer，应传入副本，原始字节单独保留供导出使用。

**PDF 兼容性风险：** 表单、注释、图层、特殊字体、已有证书数字签名、复杂旋转与裁剪边界可能产生兼容性问题；MVP 建立测试样本集，无法可靠处理的文件需明确提示。不要宣称“支持所有 PDF”。

- 注释与表单控件绘制在页面内容之上，签名若放在表单控件区域可能被遮挡；列为已知限制，并在 UI 上提示。

**浏览器存储风险：** Safari 会在用户 7 天未访问站点后清除脚本写入的存储（已安装为主屏幕应用或获得持久化授权时除外），隐私/无痕模式下关闭窗口即清空。签名库必须把“下载 PNG 备份”作为显著操作，不得暗示签名永久保存。

## 8. 非功能需求

- **性能：** 常规 10 MB、30 页文件作为测试基准；首屏和交互速度建立实际性能预算并测量，而非预先保证所有设备固定耗时。PDF.js 与导出库按需懒加载，首页不加载。
- **安全：** PDF 解析库及时更新（Renovate）；上传文件只在浏览器沙箱中处理；防止意外内容外发；不渲染不可信 HTML；禁止执行 PDF 内嵌脚本；签名库加密实现需有单元测试覆盖（加解密往返、错误 PIN、篡改密文时报错）。
- **CSP（独立于模板现有策略）：**
  ```
  default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; worker-src 'self' blob:;
  style-src 'self' 'unsafe-inline'; font-src 'self' data:; img-src 'self' data: blob:;
  connect-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'
  ```
  `'wasm-unsafe-eval'` 供 PDF.js wasm 解码器使用；若实测确认回退路径即可满足，可移除。不允许任何第三方来源。`frame-ancestors 'none'` 同时防止签名库页面被嵌入第三方页面实施点击劫持。
- **可用性：** 按钮有禁用/加载/错误状态；移动端触控热区合理（不小于 44×44 px）；有清楚的空状态和文件错误提示。
- **无障碍：** 语义化控件、键盘可达、可见焦点、图标有标签；拖放不是唯一上传方式；签名实例可用键盘移动与删除。
- **浏览器：** 当前稳定版 Chrome、Edge、Safari、Firefox；移动端优先 iOS Safari、Android Chrome。
- **隐私：** 不添加不必要第三方跟踪、上传服务和文档内容日志；错误日志不得包含文件名或内容。

## 10. 关键验收测试用例

1. 单页 A4 竖版，手写签名放右下角，导出位置一致。
2. 10 页 PDF，分别在第 1、5、10 页签名，导出各页对应正确。
3. 横版与竖版混排，缩放/切换页不产生漂移。
4. PDF 页面已有 90°/180°/270° 旋转时，签名显示与导出一致，且导出后签名方向为正。
5. 页面使用非默认 CropBox（原点不为 0,0）的 PDF，签名坐标正确。
6. 上传透明 PNG 后，导出透明背景正确；JPG 背景按原图保留。
7. 连续拖动、缩放、删除多个实例，其他实例不受影响。
8. 触屏手写时笔画连续，页面不随绘制滚动。
9. PDF 打开密码保护、仅权限限制、损坏、非 PDF 文件、超限文件均显示明确错误。
10. 通过浏览器网络检查确认用户 PDF 和签名没有上传，且无第三方域名请求。
11. 导出结果在 Chrome / Edge / Acrobat Reader 中可见且页数正确。
12. 多次导出不重复叠加旧签名；刷新后 PDF 与未保存签名不自动恢复。
13. 含 CJK 字体（嵌入与未嵌入）的 PDF 预览正常。
14. 已含数字签名的 PDF 导入时显示警告。
15. 带 EXIF 旋转信息的手机照片作为签名，方向正确；超过 2000 px 的图片被缩小后导出清晰。
16. 同一签名放置 10 个实例（含批量），导出文件体积只增加约一份图像大小。
17. 保存签名到签名库，关闭浏览器后重新打开，直接选用该签名完成另一份 PDF 签署。
18. 设置 PIN 的签名：IndexedDB 中仅有密文；错误 PIN 无法解锁；正确 PIN 解锁后本会话内免重复输入，点击“锁定”后需重新输入。
19. 签名库导出 PNG 后清空签名库，再上传该 PNG，签名效果一致。
20. 检查浏览器存储，确认不存在 PDF 内容或文件名。
21. 10 页合同“全部页”批量签名 + 末页添加日期，导出后各页位置正确、日期中文显示正常。
22. 批量签名后单独移动某页实例，其它页不受影响；“删除整组”只删除该组。

**测试样本集：** 用例 3、4、5 的 PDF 由脚本使用 `@cantoo/pdf-lib` 程序化生成（设置 `/Rotate`、CropBox），存放在 `tests/fixtures/`；另收集少量真实文件（扫描件、含表单、含 CJK 字体、已签名文件、多页合同）。

## 12. MVP 完成定义（Definition of Done）

## 14. 架构决策：MVP 不设服务端与管理后台

**决策：** MVP 为纯静态前端应用，不包含服务端 API、数据库与管理后台。签名库（FR-08）完全在浏览器本地实现。

**理由：**

1. **隐私定位：** “文件和签名不离开浏览器”是核心卖点。无服务器比“有服务器但承诺不上传”更可信。
2. **无可管理对象：** 没有账号、订单或服务端数据，管理后台无实际职能；文件上限等参数用构建配置即可。
3. **运维成本：** 模板服务端依赖 PostgreSQL、Redis、对象存储、邮件、认证、迁移与监控；纯静态站点几乎零运维。
4. **合规负担：** 不收集个人信息，基本不涉及《个人信息保护法》的收集、存储与告知义务（国内部署仍需 ICP 备案）。

**无服务端时的替代方案：**

| 需求         | 方案                                                          |
| ------------ | ------------------------------------------------------------- |
| 用户反馈     | 反馈邮箱、问卷链接或 GitHub Issues                            |
| 访问统计     | 可选：自建无 Cookie 统计（Umami / Plausible），需征得用户同意 |
| 错误监控     | 不做，或用户主动选择上报；上报内容不含文件名和文件内容        |
| 版本更新提示 | 前端读取同源静态 `version.json`                               |
| 公告         | 写在静态页面，随版本发布                                      |

**重新引入服务端的条件（满足任一即重新评审）：**

- 引入账号体系或付费订阅。
- 签名库需要跨设备云同步，且用户明确接受签名上传。
- 需要多人签署、签署链接、审计追踪等能力。此类需求属于产品方向调整，按《电子签名法》“可靠的电子签名”要求，通常还需 CA 证书与身份核验，不在本工具定位内。

届时可从 `bao-linfeng/agent-template` 重新引入 `apps/server` 与 `apps/admin`。
